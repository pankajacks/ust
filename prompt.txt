emo: Zero-shot, One-shot, and Few-shot Prompting with GitHub Copilot
+++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++


1. 🟢 Zero-shot Prompting

👉 Give only the task — no examples.

Prompt (comment in file):

// Write a function that formats a user's profile information into a readable string


Here, Copilot guesses what “format” means — the result is correct but generic.


2. 🟡 One-shot Prompting

👉 Provide one example to set the style or structure.

Prompt:

// Example:
// Input: { name: "Alice", age: 30, city: "Paris" }
// Output: "Alice (30) - City: Paris"
// Now write a function that follows the same format.


With just one example, Copilot understands the desired output style and follows it exactly.



3. 🔵 Few-shot Prompting

👉 Provide multiple examples to lock in the style and ensure consistency.

Prompt:

// Examples:
// Input: { name: "Alice", age: 30, city: "Paris" }
// Output: "Alice (30) - City: Paris"
// Input: { name: "Bob", age: 25, city: "Berlin" }
// Output: "Bob (25) - City: Berlin"
// Input: { name: "Charlie", age: 40, city: "London" }
// Output: "Charlie (40) - City: London"
// Write a function that formats any user's profile following the same pattern.


Multiple examples help Copilot infer structure, tone, and formatting rules with high precision.

Demo 2: Zero-shot vs One-shot vs Few-shot Prompting (Backend API Example)

We’ll build an Express API route for managing tasks.

1. 🟢 Zero-shot Prompting
👉 No examples, just an instruction.
Prompt (as comment in server.js):

// Create an Express route to manage tasks

Copilot generates a generic route with minimal functionality — good start but not complete.


2. 🟡 One-shot Prompting
👉 Provide one example of desired behavior/output.
Prompt:

// Example:
// GET /tasks should return: [{ id: 1, title: "Sample Task", completed: false }]
// Now add routes to support GET, POST, PUT, and DELETE for tasks.


3. 🔵 Few-shot Prompting
👉 Provide multiple examples with expected outputs for consistency and detail.
Prompt:

// Examples:
// GET /tasks → returns all tasks as JSON
// POST /tasks with { "title": "Learn Copilot" } → creates { id: 1, title: "Learn Copilot", completed: false }
// PUT /tasks/1 with { "completed": true } → updates task 1 to { id: 1, title: "Learn Copilot", completed: true }
// DELETE /tasks/1 → removes task 1 and returns 204
// Implement these routes in Express using an in-memory tasks array


✅Takeaways for Participants
Zero-shot: Minimal skeleton, Copilot “guesses”
One-shot: Clear CRUD routes with proper behavior
Few-shot: More robust, consistent API with defaults + error handling

Build a small Flask REST API service for managing a collection of books.

3. Each book should have the fields: id (int), title (string), author (string), and year (int).

   - GET /books → return a list of all books in JSON format.

   - DELETE /books/<id> → delete a book by its id.
5. Handle error cases, such as updating or deleting a book that does not exist.
6. Return proper HTTP status codes (201 for creation, 200 for success, 404 for not found, etc.).
7. Add a simple __main__ section to run the app with debug mode enabled.

Demo: Insecure Code Review with GitHub Copilot
+++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++

1. Create an Insecure Example (Node.js + Express)

insecure_app.js

const express = require("express");
const mysql = require("mysql");
const app = express();

app.use(express.json());

const connection = mysql.createConnection({
  host: "localhost",
  user: "root",
  password: "password123", // hardcoded secret
  database: "demo"
});

// Insecure login endpoint
app.post("/login", (req, res) => {
  const { username, password } = req.body;
  
  // 🚨 Vulnerable: SQL Injection possible
  const query = `SELECT * FROM users WHERE username = '${username}' AND password = '${password}'`;
  
  connection.query(query, (err, results) => {
    if (err) {
      return res.status(500).send("Database error");
    }
    if (results.length > 0) {
      res.send("Login successful!");
    } else {
      res.status(401).send("Invalid credentials");
    }
  });
});

app.listen(3000, () => console.log("Server running on port 3000"));


2. Ask Copilot to Review the Code

In Copilot Chat, select the file and type:

/ask Review this code for security risks and suggest improvements


Step 3: Observe Copilot Response 

Step 4. Ask for a Secure Rewrite

Prompt Copilot:

/edit Rewrite this login endpoint to prevent SQL injection and secure password handling


✅ Key Takeaway for Audience
Risky patterns: Hardcoded secrets, SQL injection, plaintext passwords.
Copilot’s role: Acts like a code reviewer, flags insecure practices, and suggests secure alternatives.
Developer’s responsibility: Validate suggestions, apply fixes thoughtfully.
